## How AI claims were verified

The approach was to check each AI claim with something that runs, not to accept a session's word for it. The result is recorded with the command, the commit and the output in `docs/TEST_RESULTS.md` or `docs/BENCHMARKS.md`.

- **Numerics.** A committed closed-form test prices 1M paths from a seed frozen before the first run and checks the estimate is within 3 SE of Black-Scholes (z = −2.748; TEST_RESULTS "Closed form (Core 4)"). Every deployed job also carries its own Black-Scholes comparison (`make e2e` z = +0.854 at G3). Seed independence is tested (max |corr| 0.028 < 0.05; TEST_RESULTS "Summary", Core 2).
- **Bit-identical replay.** Golden-hash tests run inside the Lambda image (`make test-golden`), in GitLab CI (emulated amd64 on James's Mac) and natively on x86 in GitHub Actions run 38392842904. `tools/shard_crosscheck.py` showed real-Lambda shards match emulated x86 and arm64 bit for bit (10/10). `make replay-check N=20` gave 20/20 bit-identical replays across many Lambda execution environments, twice (855e8d6 and again at G3). TEST_RESULTS "Golden hash (Core 5, I5)", "Replay ×20", "G3 record".
- **Fan-in and failure handling.** Moto integration tests with a fake entropy source cover duplicate delivery, a crash between the shard write and `mark_done`, out-of-order completion, forced failure → PARTIAL, the reaper and replay. WS0's IAM allow-list fixture makes any AWS call outside HANDOFF §8.3 fail a test, even one a handler swallows. The final run is 426 passed, 98.05% coverage, `qmc_core` 100% (TEST_RESULTS "G3 record"). WS3 also mutation-checked its duplicate and `mark_failed` tests (`docs/ai-log/WS3.md`, first entry).
- **The deployed stack.** `make e2e` (submit → progress → COMPLETE → Black-Scholes → replay → bit-identical); the fail-closed drills (missing secret, then a decoy token); the DLQ drill with duplicate delivery and the alarm email; `make burst` under each limiter version; a log scan for secrets with a positive control (0 matches in 1,733 events); and `make drift-check` (destroy, orphan scan, apply from empty in 65 s, `e2e --fresh`, plan with no changes). TEST_RESULTS has a section for each.
- **Stretch goals.** The Step Functions watcher (`ValidateStateMachineDefinition`, `tools/sfn_drill.py` 6/6), the PENDING_ENTROPY burst drill, the antithetic drill (SE × 0.707, replay bit-identical), and `cost_estimate` checked against the billed duration in Lambda REPORT lines within ±15% (TEST_RESULTS "Stretch" sections).
- **Performance and cost.** `make bench` measured latency, wall clock and cold starts against the assignment's targets (BENCHMARKS "Results against the assignment's targets"). COST.md uses measured CloudWatch data, not estimates from the plan.
- **Infrastructure.** `terraform validate`, tflint and Checkov (a blocking CI job; 140 passed, 0 failed, 22 justified skips at 581563d, `docs/SECURITY.md` "Checkov suppressions"). After each apply, a plan showing no changes. WS1 and WS5 compared the deployed resources and IAM policies with the Terraform using read-only AWS calls (`docs/ai-log/WS1.md`, `WS5.md`).
- **Findings were not loosened away.** When a drill failed, the acceptance check stayed as written and the finding went to WS0 and James for a decision (TEST_RESULTS, the cost and PENDING_ENTROPY findings).

### AI claims that turned out wrong

Plan assumptions corrected by measurement:

- **Qrypt rate-limit cap.** The plan's cap of 15 calls per 10 s window (from arithmetic) held our side, but Qrypt's trial key enforced its own sliding limit. The cap went 15/10 s → 10/10 s → 1 per 1 s window → a 2 s minimum gap (contract changes 004, 005, 006), each step forced by a burst or bench run. `docs/DECISIONS.md` D10 "History"; TEST_RESULTS burst sections; BENCHMARKS "Qrypt behaviour seen during the run (R24)".
- **Qrypt's answer to a bad token.** The handoff mapped 403 to `QRYPT_QUOTA_EXHAUSTED`, expecting 401 for a bad token. The decoy-token drill got 403, so a bad token was reported as an exhausted quota. Fixed by contract change 003 (`QRYPT_FORBIDDEN`). TEST_RESULTS "Fail-closed drill with a decoy token"; DECISIONS D41.
- **`kms:Decrypt`.** The plan held a conditional `kms:Decrypt` grant in reserve. The first live submit read the SecureString with `ssm:GetParameter` alone, so it was left out. DECISIONS D39; `docs/ai-log/WS2.md` (G1 live check).
- **Terraform and the project SCP.** `runtime_management_config` is not a block on `aws_lambda_function` in provider 6.68 (a separate resource is used, D38). The SCP denies IAM groups, so the grader policy is inline on the user (D37). The SCP also blocks the email verification for direct Budget subscribers, so Budget alerts go through SNS only (D43). `docs/ai-log/WS1.md`, first and seventh entries.
- **`force_destroy` on the grader user.** WS1 set it in QMC-113. Destroy then failed on `iam:DeleteLoginProfile`, which the SCP denies; only a real teardown caught it. DECISIONS D44; TEST_RESULTS "Finding: destroy blocked by the SCP"; `docs/ai-log/WS1.md` (drift-check entry).
- **Cost estimate.** The first `cost.estimate` formula under-reported compute about 5×. After contract change 009 cold starts passed (0.856×) but warm jobs came in at 0.170×, because billed work after the shard write was not recorded. Fixed with a calibrated `WORKER_OVERHEAD_MS` of 22 (0.887× and 1.015× on fresh jobs). TEST_RESULTS "Cost re-run after contract change 009" and "Cost validation with `WORKER_OVERHEAD_MS = 22`".
- **PENDING_ENTROPY backoff.** All queued seeders slept the same 2/4/6/6 s and raced for one slot, so a 10-job burst seeded one job per wave: 5 of 10 FAILED. Fixed by "wait for slot + jitter" (MR !57); the re-run completed 10/10. TEST_RESULTS "PENDING_ENTROPY burst drill".
- **The PENDING_ENTROPY seeder** had two bugs (duplicate delivery, and a job left QUEUED with no messages), found in WS3's review of MR !43 and fixed in MR !44. `docs/ai-log/WS3.md`, afternoon entry.

Mistakes the sessions made in their own work, caught and corrected:

- WS4's burst tool stopped polling logs early and printed a false "no Qrypt 429" and "max 1 Qrypt call"; WS5 caught the max, which was 2. Every affected line is listed in TEST_RESULTS. `docs/ai-log/WS4.md`, `WS5.md`.
- WS4 first described the Lambda hosts' AVX-512 as "masked"; they report none. Two unverified details and one prediction were removed from BENCHMARKS. `docs/ai-log/WS4.md`.
- WS1 first counted 14 distinct Checkov checks skipped; there were 13. WS1's contract change 005 variable description gave a rolling 10 s bound of 10; it is 11. `docs/ai-log/WS1.md`, `WS5.md`.
- WS5 twice wrote a reason no one had recorded (D10's 1 s windows, D45's VaR) and removed both before merge. `docs/ai-log/WS5.md`.
- WS5's dashboard render called the billed `GetMetricWidgetImage` (about $0.0006), disclosed in `docs/COST.md` "One known non-free call". `docs/ai-log/WS5.md`.
- WS0 merged MR !3 without running `ruff format` (main went red, fixed in !4), and a combined `git push` refspec silently skipped `main` (caught by a sha check). `docs/ai-log/WS0.md`, integrator entry.
